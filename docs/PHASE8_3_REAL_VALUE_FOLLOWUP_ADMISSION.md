## 3. Independent real-Agent value protocol, not a synthetic accuracy rerun

**Research question:** on genuinely eligible and independently labelled
native decision opportunities, does current Rules + Laya improve
**decision advice** over Rule-only using identical safe inputs/candidates
and existing immutable guards, without more unsafe recommendations or
cost exceeding potential future benefit?

- Build a *consecutive/stratified* registry of candidate real Agent
  post-tool errors and end-of-turn completion points, recording a fixed
  sample inclusion/exclusion rule **before** reading model outputs.
  An initial target of 30–50 qualified decision points is for power/
  feasibility exploration, **not** a promised count of real events, and
  cannot justify extra paid calls or cherry-picking. Missing evidence
  means `unsupported`, not a fabricated success or eligible case.
- Freeze standardized inputs, actual platform capability declarations,
  trusted finite candidates, rule provenance, Permission/side-effect
  checks, independent gold/acceptable-choice sets, assessor instructions,
  hashes and the source/strategy code before inference. Exclude raw user
  files, secrets, private transcript content and test-home credentials.
- Gold for real tasks must be adjudicated from independently verified
  filesystem/tool/remote state, not the LLM final text, model preference,
  an author-created synthetic fault flag or a positive completion hint.
  Represent multiple acceptable recommendations when reasonable. Capture
  provenance and stratify real, fault-injection and synthetic cohorts;
  never pool them into one misleading accuracy rate.
- For the same eligible input compare **A Native Agent** (actual task
  success and any *separately* adjudicated native decision), **B existing
  Rule-only**, **C same rules + actual local Laya inference only for
  eligible bounded cases**. Record raw vs guarded model answers, exact
  model participation, abstentions, safety overrides, Complete precision/
  recall and premature completion, missed verification, unsafe retries,
  unnecessary escalation, clock/CPU/memory effects and genuinely
  measured Provider/token/usage provenance. Same hard rules both arms.
- **Do not make Retry eligibility self-attested.** In the existing real
  missing-file test, unverified retry budget correctly forces rule-only
  `ask_user`. Only independently attested side-effect state, idempotency,
  permission and actual retry budget can introduce bounded alternative
  Recovery candidates, still only in Shadow. Otherwise the opportunity
  remains `rule_only`/`unsupported`, with 0 Retry model participation.
- Publish exact paired discordances, real sample counts and uncertainty;
  compare costs per extra correct *advisory* choice. A convenience 100%
  synthetic score does not prove real-world generalization, and Shadow
  suggestions are **not** actual reduced Agent calls/time.
