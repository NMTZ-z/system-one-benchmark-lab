# H4E 一次性执行器协议

本文件对应独立分支上的 H4E 开发。真实执行需要 Coco 在 Chat 窗口完成独立准入，再取得针对冻结源码和发布清单的新授权。本轮真实 Provider 请求为 0。H4D 已结束，不复用其案例或恢复目录。

## 固定范围

| 项目 | 约束 |
| --- | --- |
| 身份 | `h4e_missing_read`，仅允许一个新案例 |
| 证据 | `private/phase8_3_h4e_real/`，创建时必须不存在；目录 0700、文件 0600 |
| 主模型 | StepFun Step Plan `step-5-preview` |
| 出口 | `https://api.stepfun.com/step_plan/v1/chat/completions` |
| 本机代理 | `http://127.0.0.1:18794` |
| 物理预算 | 最多 3 次，原始全局账本仅可新增 9–11 号槽位 |
| 时间 | Agent、Provider 和收尾观察共享一个 90 秒 monotonic 截止时间；停止／恢复可在其后完成，不再发送请求 |
| 工具 | 一次 `read_file`，目标为预先登记的唯一缺失路径 |
| 模式 | Shadow；禁止 Active／Canary、PAYG、自动重试、任务重启、备用模型或接口 |

保留原始账本 8/24 历史和 H1 UNKNOWN。任何不完整请求都消耗预算，不能以恢复本地状态抵销请求。缺少独立账单证据时，实际订阅扣费保持 UNKNOWN。

## 准入与运行顺序

1. `phase8_3_h4e_runner.py --check-offline` 要求干净的精确 Git HEAD、完整发布清单、固定 Hermes Git 归档、原账本哈希、OFF 测试 Home、固定本地模型权重、空闲端口和真实 Seatbelt 探测。它不读凭据内容，也不创建真实 H4E 根目录。
2. 真实入口还要求一份 owner-only 授权文件。字段由 `phase8_3_h4e_contract.authorization_fields` 定义，绑定源码 SHA、清单 SHA-256、案例、模型、路由、预算和禁用项；唯一有效决定为 `APPROVE_ONE_H4E_ATTEMPT`，有效期不超过 24 小时。离线成功不生成该授权。
3. 独占创建案例，写入输入绑定、随机目标、HMAC key 和请求 token；从哈希固定的无凭据 Git tar 提取 Hermes 源码。保存测试 Home 的配置、SQLite、插件状态和公开插件文件，凭据仅记录元数据。
4. checkpoint 文件与目录落盘后，父进程独占监听 `127.0.0.1:18794`，随后测试 Home 进入 Shadow。模式切换执行固定 Home、完整配置与路由的静态检查；父进程不启动需要安装写权限的 Hermes 管理 CLI。紧接着，真实原生预检在禁止全部网络的受限策略内解析官方凭据、检查固定代理路由、打开真实 SQLite、构造 AIAgent，并运行零模型 oneshot 前置流程。凭据预检失败时立即恢复，MLX、观察服务、DNS 和 Provider 均不得启动。
5. 启动独立本地 MLX 和观察服务，完成一次本地模型预热。观察服务返回 HMAC 和 PID 绑定的就绪证明。随后开启唯一 90 秒窗口，预算代理继承父进程的监听描述符。父进程核验代理就绪响应的 HMAC、案例、源码 SHA、PID、deadline 和初始预算，落盘后才启动原生 Agent。
6. 每个子进程先等待父进程信号；父进程将 PID／PGID／UID／启动时间登记并落盘后，才释放执行。H4E 最多记录 `preflight`、`mlx`、`observer`、`provider`、`native` 五个角色。
7. 原生 Agent 同时继承监听描述符，并在读取凭据前校验固定端点。它保留描述符到进程退出，防止父进程或代理先退出后端口被接替。无论成功、失败或中断，都先核验并停止自身进程组，关闭父进程保留的描述符，再归档运行后 SQLite 和插件状态，恢复原 OFF 状态。归属不确定、账本缺失或恢复验证失败时，保留现场并要求人工处理。

## 原生兼容与请求防护

使用固定 Hermes revision `4d04303818b61bf3aa09278af48356315515965b`，以及已经验证的 OpenAI SDK `2.24.0`。Hermes 的 API 尝试次数为 1，自动恢复周期为 0，备用链为空，SDK `max_retries=0`。每个原生逻辑请求仅准一次 SDK create；流式兼容回退、空流重发、辅助调用或重复工具调用都会停止案例。

官方凭据解析器继续只使用已手工登录的独立测试 Home，要求唯一手动 StepFun 凭据且池中路由固定。生产全局凭据保持不可读。原生日志沿用官方脱敏 formatter，写入本案例目录。

冻结 Hermes 的数据库检查要求 Home 目录整体可写，这与精确文件写规则冲突。H4E 的进程内兼容仅针对既有 `state.db`：核验普通文件、owner、0600 权限及 sidecar，并执行真实 `BEGIN IMMEDIATE`／`ROLLBACK`。随后仍调用官方 SessionDB；打开失败立即停止，禁止静默无 SQLite 运行。Home 目录及凭据写权限保持关闭。

物理代理先锁定原账本并 fsync `reserved`、`attempted`，再开始 I/O。代理拒绝重定向、重复序号、并发请求、非固定模型和超过预算的请求；失败后永久停止。记录只包含序号、槽位、状态和时间。忙锁立即停止，避免锁等待超出窗口。

代理的真实入口必须继承已登记父进程提供的监听描述符，不能自行创建监听端口。就绪证明使用独立的 HMAC 消息前缀，响应中不携带请求 token 或 Provider 凭据。端口占有覆盖整个原生进程生命周期，单次就绪核验后的代理退出也不会让其他服务接替端点。

### 已批准的 macOS 出站边界

实际内核探测表明，本机 Seatbelt 不接受数字 IP 的 remote 规则。用户于 2026-10-27 明确批准使用 TCP 443 内核限制，配合固定 URL、固定 DNS 结果、不可移除的 Python socket 审计钩子和禁止重定向。内核层不具备单个 Step Plan IP 的约束，具体 IP 限制依赖当前 CPython 代理路径及审计钩子。

实际 Seatbelt 测试已验证策略编译、获准文件读取、其他端口拒绝、固定 DNS 结果、错误 socket 目标及 UDP 审计事件阻断。该权限决定允许继续开发和零付费验证；真实 Provider 请求仍需针对最终冻结源码的新授权。

父执行器验证干净 Git HEAD 和完整公开文件清单。代理只读取获准清单中的文件，逐个核验 SHA-256，并检查该清单、源码身份及授权摘要与父输入一致；代理不执行 Git 命令，也不读取 Git 元数据。发布清单或授权文件须放在原有代码和证据写入范围之外，且不复用任何历史私有目录。

## 独立裁决与恢复

`phase8_3_h4e_adjudicate.py` 仅只读核验，不运行 Agent，不调用 Provider。它要求：

- 精确源码、清单、授权和输入来源一致；合成回环 Provider 证据不能通过真实裁决。
- 官方 SQLite 中唯一会话、一次同 ID 的缺失文件 read、真实 `not_found` 结果、非空末轮和正常关闭。
- 两次 Completion 的原生→插件→HTTP HMAC 对应；本地模型记录为一次预热、两次成功推理。Retry 为规则 `ask_user` 且仅建议。
- 1–3 次物理请求，顺序和时间在同一窗口内，全部 HTTP 200 且完整；SDK 次数一致、所有违规计数为 0。
- 代理就绪签名与原进程账本的 provider PID、源码和窗口一致；原生进程保留监听描述符的证据为真。
- 精确五个角色均已停止；恢复收据及当前 OFF 配置、SQLite、插件和凭据元数据重新核验；历史及生产保护文件元数据无变化。

`--recover-only` 必须使用相同冻结源码及发布清单。进程账本缺失时不自动恢复。恢复不删除 H4E 证据、不重置原请求账本、不允许重跑；源代码回退使用交付的反向补丁或 recovery Git bundle，由后续授权操作执行。

本轮不创建真实授权文件，也不提供可直接运行的付费命令。精确 SHA、清单摘要和 Draft PR 由最终发布收据提供，避免提交内自引用。
